📖 Notes
What is Express? Express is a web framework built on top of Node.js for creating web servers and APIs. It reduces the boilerplate required when using Node's built-in http module. 
With raw Node.js we manually handled:
req.method 
req.url
URL parsing
request body chunks
JSON.parse()
res.writeHead()
res.end()

Express provides simpler APIs such as:
app.get()
app.post()
app.put()
app.delete()
req.params
req.query
req.body
res.json()
res.status()

Why does Express exist?
Express exists because manually handling HTTP requests with Node's http module becomes large and difficult to maintain as an application grows.
Express provides:
simpler routing
middleware
easier request/response handling
cleaner code
better project organization

What is app?
const app = express();
app is the Express application object.
It is used to configure:
routes
middleware
server behavior
error handling

Example:
app.get("/api/status", handler);
app.post("/api/missions", handler);
app.use(middleware);

What is a route?
A route is a rule that determines what code should execute when a request with a particular HTTP method and URL arrives.
A route consists of:
HTTP method + URL path + handler
Example:
app.get("/api/missions", (req, res) => {
    res.json(missions);
});

The route is:
GET /api/missions
What does app.get() do?
app.get() registers a handler for incoming GET requests. It does not send a GET request.

Example:
app.get("/api/status", (req, res) => {
    res.json({
        status: "running"
    });
});

This means:
When a GET request arrives at /api/status, execute this function.

What does app.post() do?
app.post() registers a handler for incoming POST requests.
Example:
app.post("/api/missions", (req, res) => {
    res.status(201).json({
        message: "Mission received"
    });
});
POST is generally used when the client wants to create/send data.

What is req.params?
req.params contains values captured from route parameters.
Example:
GET /api/missions/101
Route:
app.get("/api/missions/:id", (req, res) => {
    console.log(req.params.id);
});
Result:
101
Route parameters are part of the URL path.

/api/missions/:id
                 ↑
            req.params.id
            
What is req.query?
req.query contains query parameters appearing after ?.

Example:
/api/missions?difficulty=hard

Code:
const { difficulty } = req.query;
Result:
hard

Multiple query parameters can also be used:
/api/status?name=Jayaprakash&day=16
req.query.name
req.query.day
Difference
req.params
→ values embedded in the route path


req.query
→ values after ?
Example
/api/missions/2
              ↑
          req.params.id

/api/missions?difficulty=hard
                    ↑
                req.query

What is req.body?
req.body contains data sent by the client in the HTTP request body.
Example:
{
  "title": "Learn Express",
  "difficulty": "Hard"
}
After JSON parsing, Express makes it available through:
req.body
What does express.json() do?
app.use(express.json());

It is middleware that parses incoming JSON request bodies and makes the resulting JavaScript object available as:
req.body
Without it, JSON request bodies are not automatically available in this form.
Before Express, with raw Node.js, we had to manually do:
req.on("data")
req.on("end")
JSON.parse()

Express simplifies that process.

What is middleware?
Middleware is a function that runs during the request-response lifecycle.
Example:
app.use((req, res, next) => {
    console.log(req.method, req.url);
    next();
});

Middleware can:
inspect requests
modify requests or responses
perform authentication
log requests
validate data
parse data
handle errors
pass control to the next middleware

What is next()?
next() passes control to the next middleware or route handler.

Example:
app.use((req, res, next) => {
    console.log(req.method, req.url);
    next();
});
Without next(), if the middleware does not send a response, the request can remain stuck.

Flow:
Request
   ↓
Middleware
   ↓
next()
   ↓
Next middleware / route
   ↓
Response
🏗️ Backend Architecture

Instead of putting everything into one large file, we separated responsibilities.
server/
├── controllers/
│   └── missionController.js
│
├── data/
│   └── mission.js
│
├── routes/
│   └── missionRoutes.js
│
├── app.js
└── server.js

What is a Controller?
A controller contains the logic that handles a request.
Example:
export function getMissions(req, res) {
    res.json(missions);
}
The controller decides:
What should happen when this request reaches the application?

What is a Router?
A router defines the relationship between HTTP methods, paths, and controllers.
Example:
missionRoutes.get("/", getMissions);
missionRoutes.get("/:id", getMissionById);
missionRoutes.post("/", createMission);
missionRoutes.put("/:id", updateMission);
missionRoutes.delete("/:id", deleteMission);

The router decides:
Which controller should handle this request?

Route vs Controller
Route
missionRoutes.get("/:id", getMissionById);
Answers:
Which request should trigger the function?

Controller
export function getMissionById(req, res) {
    // logic
}
Answers:
What should happen after the request arrives?

What is express.Router()?
const missionRoutes = express.Router();
It creates a modular router that allows related routes to be grouped together.
Example:
missionRoutes.get("/", getMissions);
missionRoutes.get("/:id", getMissionById);
missionRoutes.post("/", createMission);

Then in app.js:
app.use("/api/missions", missionRoutes);
Express combines the prefix and router paths.
Therefore:
/api/missions + /
→ GET /api/missions

/api/missions + /:id
→ GET /api/missions/:id

Why separate app.js and server.js?
app.js Responsible for configuring the Express application:
middleware
routes
404 handling
application configuration

server.js
Responsible for starting the server:
app.listen(3000);
This separation makes the application easier to test and maintain.

Filtering with Query Parameters
We also implemented:
GET /api/missions?difficulty=hard
Controller:
const { difficulty } = req.query;

if (difficulty) {
    const filteredMissions = missions.filter(
        (mission) =>
            mission.difficulty.toLowerCase() ===
            difficulty.toLowerCase()
    );


    return res.json(filteredMissions);
}
res.json(missions);
This lets the same endpoint return either:
all missions or: only hard missions depending on the query parameter.

In-Memory Data Our missions are currently stored in a JavaScript array:

export const missions = [
    {
        id: 1,
        title: "Learn JavaScript",
        difficulty: "easy"
    }
];
This means changes are temporary.
For example:
DELETE mission 1
        ↓
mission removed from memory
        ↓
server restarts
        ↓
original array loaded again
        ↓
mission 1 exists again

This happens because the data is stored in the Node.js process memory rather than a database.

   ↓
