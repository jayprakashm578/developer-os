📖 Notes
What is a Mongoose Model?
A Mongoose Model is the object created from a Mongoose Schema that allows the application to interact with MongoDB documents.
The Schema defines: structure, data types, validation rules, defaults

The Model provides operations for:
creating documents
finding documents
updating documents
deleting documents
A simple way to remember it:
Schema → defines the rules
Model → performs database operations

What is MongoDB _id?
MongoDB automatically gives every document a unique identifier called _id.
This identifier allows MongoDB to uniquely identify each document.
Mongoose commonly represents this identifier using an ObjectId.
An ObjectId is not simply an ordinary string. It is a MongoDB data type that is usually displayed as a 24-character hexadecimal value.
The important idea is:
_id uniquely identifies a document.

What is ObjectId?
ObjectId is the default identifier type used by MongoDB for many documents.
It looks similar to a long hexadecimal string, but internally it is an ObjectId data type.
It is useful because every document needs a unique identity so that operations such as finding, updating, and deleting a specific document can be performed.

What is find()?
find() is used to retrieve multiple documents that match a condition.
If no condition is provided, it can return all documents in the collection.
Therefore:
find() → multiple matching documents
The result is generally an array of documents.

What is findById()?
findById() is used to find a specific document using its MongoDB _id.
Therefore:
findById() → one specific document
It is especially useful for routes such as:
GET /api/missions/:id

What is create()?
The Mongoose create operation is used to create a new document in MongoDB.
The application sends the data to the Model, Mongoose validates it according to the Schema, and MongoDB stores the resulting document.
Flow:
Request → Controller → Service → Model → MongoDB

What is findByIdAndUpdate()?
It is used to update a document by its _id.
It allows the application to find the required document and modify it.
It is commonly used for PUT or PATCH operations.

What does new: true mean?
new: true tells Mongoose to return the updated document after the update.
It does not mean that a new document is being created.
Without this option, the returned value can represent the document before the update.
Therefore:
new: true → return the updated version

What does runValidators: true mean?
runValidators: true tells Mongoose to run the Schema validation rules when performing an update.
This is important because we want the updated data to follow the same rules as newly created data.
For example, if a mission title must contain at least five characters, an update should not be allowed to bypass that requirement.

What is findByIdAndDelete()?
It is used to find a document using its _id and remove it from MongoDB.
Therefore:
findByIdAndDelete() → find a specific document and delete it
If the document does not exist, the service can return a not-found result.

Why do we use async/await with MongoDB?
Database operations take time because the application communicates with another system.
Therefore MongoDB operations are asynchronous.
await allows the program to wait for the database operation to finish while keeping the code easier to read.
This is why database services commonly use asynchronous functions.

Why should database operations stay in the service layer?
The service layer is responsible for business logic and data operations.
Keeping MongoDB operations there gives us a clean separation:
Controller → HTTP handling
Service → business and data logic
Model → MongoDB interaction
This makes the application easier to maintain and test.

What is filtering?
Filtering means returning only the documents that satisfy a particular condition.
For example, the API can allow the client to request only missions whose difficulty is hard.
Instead of returning every mission, MongoDB returns only the matching documents.

What are query parameters?
Query parameters are values added to the URL after a question mark.
For example, an API might receive parameters such as:
difficulty
search
page
limit
sort
They allow clients to customize the data they receive without creating a separate route for every possible combination.

What is $regex?
$regex allows MongoDB to perform pattern-based searching on string fields.
It is useful for search functionality.
For example, a search for node can match titles containing:
Node
node
NODE
when case-insensitive matching is enabled.

What does case-insensitive searching mean?
Case-insensitive searching means uppercase and lowercase letters are treated as equivalent.
For example: Node, node, NODE
can all be considered matches.
This makes search functionality more user-friendly.

What is sorting?
Sorting determines the order in which documents are returned.
Documents can be sorted by fields such as:
created date
updated date
title
difficulty
Sorting can be: Ascending or Descending

Ascending vs Descending
Ascending means the values move from smaller/earlier to larger/later.
For dates:
oldest → newest
Descending means:
newest → oldest

In MongoDB sorting:
1 → ascending
-1 → descending

Therefore:
createdAt ascending → oldest first
createdAt descending → newest first

What is pagination?
Pagination means dividing a large result set into smaller pages.
Imagine there are 100 missions.
Instead of returning all 100 at once, the API might return 10 missions per page.
The client can then request:
Page 1
Page 2
Page 3
and so on.
Pagination makes APIs more efficient and easier for users to consume.

What is limit?
limit specifies the maximum number of documents returned.
For example, a limit of 5 means:
Return at most 5 documents.
It is important for performance because an API should not unnecessarily return huge amounts of data.

What is skip()?
skip() tells MongoDB to ignore a certain number of matching documents before returning results.
It is commonly used together with limit() to implement pagination.
For example:
page 1 skips 0 documents
page 2 skips the first page
page 3 skips the first two pages

Pagination formula
The number of documents to skip is calculated as:
(page − 1) × limit
For example:
Page 1 with limit 5:
(1 − 1) × 5 = 0

Page 2:
(2 − 1) × 5 = 5

Page 3:
(3 − 1) × 5 = 10
This allows the application to retrieve the correct section of the dataset.

Why should we restrict the maximum limit?
A malicious or careless client could request an extremely large number of documents.
For example, a request could ask for hundreds of thousands of records.
That could increase:
database load
memory usage
network usage
response time
server resource consumption
Therefore APIs should usually enforce a reasonable maximum limit.

What is countDocuments()?
countDocuments() returns the number of documents matching a specified condition.
It is useful for pagination because the API needs to know:
total number of matching documents
total number of pages
For example, if there are 20 matching documents and the limit is 5, the API knows that there are 4 pages.

Why do we return pagination metadata?
Returning only the documents is not enough for a frontend.
The frontend may also need to know:
total number of documents
current page
number of documents per page
total number of pages
This information allows the frontend to build pagination controls such as:
Previous | 1 | 2 | 3 | 4 | Next

What is field selection?
Field selection means requesting only the fields that are needed.
A document may contain many fields, but a particular endpoint may only need:
title
difficulty
Returning fewer fields can reduce unnecessary data transfer and make responses smaller.

What is lean()?
lean() tells Mongoose to return plain JavaScript objects instead of full Mongoose documents.
Normal Mongoose queries return objects with additional Mongoose functionality.
When we only need to read and return data, plain objects are often sufficient.
Therefore:
Normal query → Mongoose documents
Lean query → plain JavaScript objects
lean() is particularly useful for read-heavy operations where document methods are not required.

What is Promise.all()?
Promise.all() allows multiple asynchronous operations to be started concurrently and waits for all of them to finish.
For example, when retrieving paginated data, we may need:
The actual missions
and
The total number of matching documents
These are independent database operations, so they can be performed concurrently.
This can be more efficient than intentionally waiting for the first query to completely finish before beginning the second.

Why are query parameters converted from strings?
Query parameters arrive through the URL, so they are received as strings.
For example:
page=2
is received as the string "2".
But pagination calculations require numbers.
Therefore the application should convert values such as:
page
limit
into numbers before performing arithmetic.

Why should query parameters be validated?
Users can send arbitrary query values.
For example:
negative page number
extremely large limit
unsupported difficulty
invalid sort option
The backend should validate these values rather than trusting them.
This prevents unexpected behavior and protects server resources.

Combined Query
The API can now support requests combining multiple features.
For example:
difficulty = hard
AND
search = node
AND
page = 1
AND
limit = 5
AND
sort = newest
MongoDB can process the conditions together rather than retrieving the entire dataset into JavaScript first.

How the combined query works
The overall flow is:
Client sends request
↓
Express receives query parameters
↓
Controller reads the parameters
↓
Service creates the MongoDB filter
↓
MongoDB filters matching documents
↓
MongoDB sorts them
↓
MongoDB skips the required number
↓
MongoDB limits the result
↓
MongoDB returns the selected documents
↓
API returns the data and pagination metadata

Important Architecture
The backend now looks like:
Client
   ↓
Express
   ↓
Middleware
   ↓
Route
   ↓
Controller
   ↓
Service
   ↓
Mongoose Model
   ↓
MongoDB

And the query process becomes:
MongoDB
   ↓
Filtering
   ↓
Searching
   ↓
Sorting
   ↓
Pagination
   ↓
Response
