📖 Notes
What is a <form>?
    A form is an HTML element used to collect information from a user and submit that information for processing.

What is a submit event?
    A submit event occurs when a form is submitted, either by clicking its submit button or by pressing Enter while using a form field.

What does event.preventDefault() do?
    event.preventDefault() prevents the browser's default form-submission behavior so JavaScript can handle the submission without automatically reloading or navigating the page.

Difference between a click event and a submit event
    A click event happens when an element is clicked. A submit event represents the submission of a form and can occur through different methods, such as clicking the submit button or pressing Enter.

For form logic, listening to the form's submit event is generally better than listening only to the button's click event.

How do we read form values?
    We can access the value entered into an input using its .value property.
const title = missionTitle.value;

What does .trim() do?
.trim() removes whitespace from the beginning and end of a string.
const title = missionTitle.value.trim();

For example:
"   Learn React   "
becomes:
"Learn React"

What is client-side validation?
Client-side validation means checking user input in the browser before sending it to the server.
Examples include checking whether:
A field is empty.
A mission name is long enough.
A required technology is provided.

Example:
if (!title) {
    return;
}

Why should validation happen before fetch()?
Validation should happen before the API request because invalid data should not be sent to the server.

The correct flow is:

Read input
   ↓
Validate
   ↓
Create object
   ↓
Send POST request

Why isn't client-side validation enough?
Client-side validation is not a security mechanism because users can bypass JavaScript and send their own HTTP requests. Therefore, real applications need validation on both:

Client
   ↓
Server

What is a request body?
The request body contains the data that the client sends to the server.
For example:
const mission = {
    title: "Learn React",
    technology: "React",
    difficulty: "medium"
};
This object can be converted to JSON and sent as the request body.

What are HTTP headers?
HTTP headers provide additional information about a request or response.
Example:
headers: {
    "Content-Type": "application/json"
}

This tells the server that the request body contains JSON.

What is Content-Type?
Content-Type tells the receiver what format the request body is using.
For example:
"Content-Type": "application/json"
means the body contains JSON data.

What does JSON.stringify() do?
JSON.stringify() serializes a JavaScript value into a JSON string.
Example:
const mission = {
    title: "Learn React"
};
const jsonMission = JSON.stringify(mission);

The JavaScript object becomes a JSON string that can be sent in an HTTP request body.

Difference between JSON.stringify() and response.json()
JSON.stringify()
Converts:
JavaScript value
        ↓
JSON string
It is commonly used before sending JSON to a server.
response.json()
Reads and asynchronously parses the response body as JSON.
HTTP response body
        ↓
response.json()
        ↓
JavaScript value

They perform opposite-direction conversions in the common request/response workflow.

How do we send JSON using fetch()?
We use a POST request with a JSON content type and a stringified request body.
const response = await fetch(url, {
    method: "POST",

    headers: {
        "Content-Type": "application/json"
    },

    body: JSON.stringify(mission)
});
Why do we check response.ok?
response.ok tells us whether the HTTP response has a successful status.

It is generally:
200–299 → true
and: 400–599 → false
For example:
if (!response.ok) {
    throw new Error(`HTTP Error: ${response.status}`);
}

What happens after the server receives POST data?
The server processes the request body and may create or update a resource.
The server then sends an HTTP response back to the client.
In the JSONPlaceholder exercise, the response includes a generated ID that we can display in the Developer OS.
